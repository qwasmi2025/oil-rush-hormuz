Replit Generation Prompt: Top-Down Multiplayer Naval Strait Game
Title: "Hormuz Strait Navigator" - Simple Multiplayer HTML5 Web Game

Technical Stack:

Frontend: Vanilla JavaScript (ES6+), HTML5 Canvas, HTML/CSS.

Backend: Node.js, Socket.io (for real-time multiplayer).

Database (Optional but recommended): Firebase Realtime Database (to save persistent scores/states, as requested).

Objective:
Create a fully functional, simple, top-down perspective multiplayer web game where players control ships navigating a narrow strait (like the Strait of Hormuz, based on the geographical layout seen in Capture.jpg). The goal is simple survival and navigation. If a ship touches the "land" or another player, it resets or loses points.

Detailed Scope of Work
Phase 1: Core Mechanics (Client-Side HTML5 Canvas)
Rendering Engine (Canvas API): Set up an HTML5 Canvas that fills the screen. Implement a basic game loop (requestAnimationFrame).

Top-Down Assets (Simple Art Generation Prompt):

Background (Water): Deep blue, slightly textured tileable sprite or flat color (#1a4b8c).

Land (Shorelines): Use the layout from Capture.jpg as the reference shape. A stylized, simplified vector shape representing the Omani and Iranian coasts. Use a sandy beige (#e0cfa0) or rugged brown (#8c6a42).

Ship Sprites: Simple rectangular shapes with a triangular 'bow' (front). Create two different colors (e.g., Green for Player Team, Red for Enemy Team, or just randomized). Size: Small relative to the strait's narrowest point.

Boundary Line (Map Bounds): A invisible or dotted boundary just inside the land colliders.

Ship Controls & Physics:

Input: WASD or Arrow Keys for movement and rotation.

Movement: Ships must have rotational inertia (they don't turn on a dime). Use 'tank controls' (Up/Down for forward/reverse, Left/Right to rotate the ship).

Water Drag: Implement a decelerating force; when the player releases 'Up', the ship slowly glides to a stop.

Camera System (Static Level & Bounds):

The game world itself (the strait map) is fixed. The camera must follow the local player's ship (photonView.IsMine logic applied here) and smoothly clamp its position so the camera cannot show area beyond the map's defined boundaries (minBounds and maxBounds). Use Math.clamp.

Phase 2: Simple Multiplayer Logic (Node.js + Socket.io)
Server Setup: Configure a Node.js server that serves the static game files and initializes Socket.io.

Player Connection:

When a client connects, the server creates a player object with a unique ID, a random starting position on the water, and a default rotation.

The server must broadcast this new player's state to all other connected clients.

State Meticulous Mismatching (Synchronization):

The client calculates movement physics locally for its ship (to ensure smoothness).

The client only sends raw input (e.g., 'W' pressed, 'S' released, rotation angle) and its current calculated position/rotation to the server at a high frequency (e.g., 30 times/sec).

The server validates this position against the map layout (server-side collision is best, but start with client-side for simplicity).

The server then broadcasts the true position/rotation of all players back to everyone.

Clients must handle interpolation (smoothing) of other players' ships to prevent "teleportation" (the simple sync requested).

Phase 3: Game Logic & Integration
Basic Goal/Win State:

Add a "Finish Line" zone at the far end of the strait.

When a player's ship collides with this zone, the server registers a successful "transit."

Notify all players: "[PlayerName] successfully transited the strait!" and restart that player at the starting zone.

Firebase Integration (Optional Step-Up):

Connect Firebase. When a player transits successfully, increment their persistent 'Transit Count' score in the Realtime Database. Display a top 5 leaderboard on the UI.

Basic UI: Display player count, local player's transit count, and simple instructions.
